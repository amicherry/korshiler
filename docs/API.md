# Көршілер — API игры (черновик для бэкенда E-KNOT)

Сейчас все запросы обслуживает заглушка `MockServer` в `src/api.js`: данные лежат в localStorage браузера, ответы приходят с задержкой 150–450 мс, примерно 4% запросов «теряют связь» (чтобы игра умела повторять запрос). Параметр `?stable` в адресе отключает обрывы.

Чтобы подключить настоящий сервер, достаточно указать адрес в `API_CONFIG.baseUrl`: те же запросы пойдут через `fetch` с заголовком `Authorization: Bearer <session>`. Игра при этом не меняется.

## Вход

Приложение E-KNOT открывает игру по ссылке с токеном жителя: `https://…/index.html?token=<одноразовый токен>` (в демо-странице можно `#demo`).
Без токена игра работает в **гостевом режиме**: играть можно, но бонусы не начисляются.

В заглушке есть тестовые токены: `demo` (Әмина, ЖК «Нұрлы», кв. 13) и `demo2` (Арман, кв. 7).

### `POST /auth`
```json
// запрос
{ "token": "demo", "deviceId": "g-123456" }
// ответ
{ "session": "s-u-1001",
  "user": { "userId": "u-1001", "name": "Әмина", "apartment": 13, "guest": false,
            "complex": { "id": "c-17", "name": "ЖК «Нұрлы»", "city": "Астана" } } }
```

## Профиль (сохранение игры)

### `GET /profile` → `{ "profile": { … } | null }`
### `PUT /profile` ← `{ "profile": { "name", "look", "created", "seenIntro", "tours", "trust" } }`
Монеты (`coins`) и сумму бонусов (`rewardsTotal`) сервер игре менять не даёт: они меняются только по итогам тура.
### `DELETE /profile` — сброс прогресса (кнопка в настройках).

## Тур

### `POST /tours/start` ← `{ "tourId": "t1" }`
```json
{ "runId": "r-…", "startedAt": 1763280000000, "tour": { "id": "t1", "goal": 10, "floors": 5, "perFloor": 4 } }
```

### `POST /tours/finish` ← `{ "runId": "r-…", "events": [ { "t": "yes", "apt": 5, "via": "door" }, … ] }`
Сервер **сам пересчитывает подписи** по журналу событий и не верит итоговому числу из игры:
- учитываются только уникальные квартиры из этого дома, кроме квартиры героя;
- если 4+ подписи пришли быстрее чем за 15 секунд, результат считается подозрительным и обнуляется;
- повторная отправка той же попытки возвращает тот же ответ (безопасно повторять при обрыве связи).

```json
{ "signatures": 10, "online": 3, "success": true,
  "score": 1730, "best": 1730, "newBest": true,
  "coins": 75, "totalCoins": 140,
  "reward": { "tourId": "t1", "points": 50, "status": "sent" },
  "suspicious": false }
```
Тур 2 (`t2`): к подписям своего подъезда сервер добавляет онлайн-голоса двух других подъездов: `min(64, ⌊свои «да» × 1.25 + рассылки енота × 7⌋)`, рассылки считаются по событиям `{ "t": "broadcast" }`, не больше лимита енота в туре. В ответе — `own` и `remote`.

Очки: `подписи×100 + онлайн×20`, при победе `+300` и бонус за скорость.
`reward.status`: `sent` — бонусы ушли в приложение; `needs_login` — игрок гость, бонус ждёт входа через E-KNOT. Бонус даётся один раз за первую победу в туре.

Если сервер так и не ответил, игра показывает итог, посчитанный у себя, с пометкой «нет связи» — без очков, рейтинга и бонусов.

## Дом и уровни (с 17.11)

Уровни — это собрания жильцов по жалобам на дом (`L1`…`L8`: свет, домофон, крыша, подвал, площадка, лифт, антенна, вывеска).
- `POST /tours/start` отвечает `403 locked`, если предыдущая проблема ещё не отремонтирована — перепрыгнуть уровень нельзя.
- `POST /tours/finish` при победе начисляет бюджет: за первую победу `reward.first`, за повтор `reward.replay`, плюс `perExtra` за каждую подпись сверх нормы. В ответе `first: true|false`.

### `GET /house`
```json
{ "fixed": ["light"], "decor": ["bench"], "won": ["L1", "L2"], "coins": 240, "score": 120, "bonus": 12, "claimable": true }
```
### `POST /house/buy` ← `{ "id": "door" }`
Ремонт проблемы: нужно, чтобы собрание по ней было выиграно, предыдущая проблема исправлена и хватало бюджета. Украшения двора (`bench`, `flowers`, `trees`, `lamps`, `parking`) открываются после N ремонтов. Ошибки: `order`, `no_vote`, `locked`, `no_money` (402), `already` (409). Ответ — состояние дома, как в `GET /house`.
### `POST /house/claim` — бонус дня в приложение: `⌊очки ЖК / 10⌋`, раз в сутки.
### `GET /leaderboard?scope=house` — «Лучший ЖК» по очкам состояния дома; из лучших выбирают победителей розыгрыша.
