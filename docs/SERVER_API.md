# Көршілер — API игрового сервера

Версия 1 · 28.11.2026 · клиент игры 1.6.0

Этот документ — точный список запросов, которые игра уже отправляет. Сейчас на них отвечает заглушка `MockServer` (`src/api.js`), и она ведёт себя так, как описано ниже. Если сервер отвечает так же, игра заработает без доработок.

Связь с приложением E-KNOT (параметры запуска, результат тура, значки) описана отдельно — в `docs/API.md`. Вход через Telegram — в `docs/telegram.md`.

## 0. Как подключить

Адрес сервера можно задать тремя способами, пересобирать игру не нужно:

1. В `src/api.js`: `API_CONFIG.baseUrl = 'https://api.e-knot.kz/game/v1'`.
2. В `index.html` перед скриптом игры: `<script>window.KORSHILER_API = 'https://…'</script>`.
3. Для проверки — в ссылке: `https://amicherry.github.io/korshiler/?api=https://test.e-knot.kz/game/v1`.

Принимается только адрес на `https://`. Если адрес не задан, работает заглушка.

**CORS.** Игра открывается с `https://amicherry.github.io` (в будущем — с вашего домена) и из WebView. Сервер должен разрешить этот origin, методы `GET, POST, PUT, DELETE` и заголовки `Content-Type, Authorization, X-Client`.

## 1. Общие правила

- Тела запросов и ответов — JSON (`Content-Type: application/json`).
- После входа игра шлёт `Authorization: Bearer <session>`.
- В каждом запросе есть заголовок `X-Client: korshiler/1.6.0`.
- **Ошибки:** HTTP-код плюс тело `{ "error": "<код>" }`. Код ошибки игра показывает игроку понятным текстом. Коды перечислены у каждого запроса.
- `401` — сессия недействительна. Игра один раз заново проходит `/auth` и повторяет запрос.
- Сеть, таймаут (12 с) или `5xx` — игра повторяет запрос 3–4 раза с паузой.
- `4xx` игра не повторяет.
- **Повторы должны быть безопасны.** `POST /tours/finish` с тем же `runId` возвращает тот же ответ и не начисляет ничего второй раз.
- **Сервер — источник правды.** Монеты, победы, значки и рейтинг считает только сервер. Клиент присылает события, а не итоговые числа.

## 2. Вход

### `POST /auth`

Запрос (поля зависят от того, откуда запущена игра):

```json
{
  "token": "eyJ…",                         // из приложения E-KNOT (?token=…), иначе null
  "deviceId": "g-123456789",               // постоянный id устройства для гостя
  "tg": {                                  // только при запуске из Telegram
    "initData": "query_id=…&user=…&hash=…", // Telegram.WebApp.initData как есть
    "contact": "contact=…&hash=…",          // строка ответа requestContact как есть
    "phone": "77011234567"                  // номер (для удобства; верить только подписанному contact)
  },
  "launch": { "name": "Әмина", "complex": "ЖК Нұрлы", "level": 3, "tour": 1, "title": "chairman" }
}
```

Что делает сервер:

1. **Если есть `tg`:**
   - проверить подпись `initData` токеном бота и `auth_date` не старше суток;
   - проверить подпись `contact` и что `contact.user_id` совпадает с `user.id` из `initData`;
   - найти или создать пользователя по номеру телефона.

   Подробно — в `docs/telegram.md`.
2. **Если есть `token`:** проверить токен приложения E-KNOT.
3. **Иначе** — гость (`guest: true`): играть можно, бонусы в приложение не уходят.
4. `launch.tour` (сколько туров уже пройдено) учитывать только для доверенного пользователя.

Ответ:

```json
{
  "session": "s-…",
  "user": {
    "userId": "u-1001", "name": "Әмина", "phone": "77011234567",
    "complex": { "id": "c-17", "name": "ЖК «Нұрлы»", "city": "Астана" },
    "apartment": 13, "level": 3, "title": "chairman",
    "guest": false, "telegram": true
  }
}
```

Ошибки: `400 bad_request`, `403 bad_signature` (подпись Telegram не сошлась), `403 bad_token`.

## 3. Профиль (сохранение игры)

| Запрос | Тело | Ответ |
|---|---|---|
| `GET /profile` | — | `{ "profile": { … } \| null }` |
| `PUT /profile` | `{ "profile": { … } }` | `{ "ok": true }` |
| `DELETE /profile` | — | `{ "ok": true }` — сброс прогресса (кнопка «Сбросить» в настройках) |

`profile` — сохранение игры: имя, внешность, пройденные подсказки, доверие жильцов и т. п. Это JSON до ~20 КБ. Хранить его целиком и не разбирать.

Поля `coins`, `rewardsTotal`, `quizPaid` и `quizBest` клиент перезаписать не может. При `PUT` сервер подставляет в них свои значения.

## 4. Собрание (тур)

### `POST /tours/start`

Запрос: `{ "tourId": "L3" }`.

Ответ:
```json
{ "runId": "r-…", "startedAt": 1795800000000,
  "tour": { "id": "L3", "goal": 51, "floors": 13, "perFloor": 8 } }
```

Ошибки:
- `404 no_tour`;
- `403 locked` — тур не открыт: каждый тур открывается после победы в предыдущем.

### `POST /tours/finish`

Запрос:
```json
{ "runId": "r-…",
  "events": [
    { "t": "online", "apt": 14, "via": "notify" },
    { "t": "yes",    "apt": 14, "via": "notify" },
    { "t": "no",     "apt": 22, "via": "door" },
    { "t": "abstain","apt": 31, "via": "online" }
  ] }
```

**`t` — тип события:**
- `yes` — за;
- `no` — против;
- `abstain` — воздержался;
- `online` — жилец перешёл в приложение. Это не голос.

**`via` — откуда голос:**
- `door` — у двери;
- `paper` — бумажный бюллетень;
- `proxy` — по доверенности;
- `online`, `notify`, `call`, `redial`, `chat` — через приложение или енота;
- `owner` — собственник.

**Как сервер считает итог** (так же, как заглушка):
1. Голос квартиры — её последнее событие `yes`, `no` или `abstain`. Если после `yes` пришло `no` или `abstain`, они игнорируются: «за» не отзывается.
2. Не считаются:
   - квартиры вне `1…floors×perFloor`;
   - квартира героя (`heroApt` = 53);
   - кладовые 1–4.
3. Подозрительная попытка — `seconds < 15` и больше 3 голосов «за». Тогда всё обнуляется, в ответе `suspicious: true`.
4. Правило победы (`voteOutcome` в `src/content.js`):

   | Тур | Код | Правило | Нужно «за» | Кворум | Бюджет за 1-ю победу, ₸ | Значки |
   |---|---|---|---|---|---|---|
   | L1 | initiative | «за» ≥ goal | 10 | — | 0 | initiative_group |
   | L2 | chairman | явка ≥ кворум и «за» > ½ явки | 26 | 51 | 780 000 | chairman_elected, council_elected |
   | L3 | tariff | «за» ≥ goal | 51 | — | 1 380 000 | tariff_approved |
   | L4 | letnik | «за» ≥ goal | 51 | — | 2 580 000 | letnik_approved |
   | L5 | construction | «за» ≥ goal (⅔) | 67 | — | 3 780 000 | construction_approved |
   | L6 | lift | «за» ≥ goal | 51 | — | 2 880 000 | lift_approved |
   | L7 | capital | «за» ≥ goal | 51 | — | 0 | all_tours |

   В L2 нужно `max(26, floor(явка/2)+1)` голосов «за», явка = за + против + воздержались.
5. **Первая победа в туре:**
   - бюджет тура (`coins`) зачисляется один раз;
   - тур добавляется в `won`;
   - ремонты-решения этого тура (`kind: construction`) сразу попадают в `fixed`;
   - для не-гостя создаётся награда в приложение: `points = 50 + n×10`, плюс значки.
6. **Очки для рейтинга:** `score = за×100 + онлайн-за×20 + (победа ? 300 + max(0, round(600 − секунды))×2 : 0)`.

Ответ (повторный запрос с тем же `runId` возвращает то же самое):
```json
{ "signatures": 52, "own": 52, "online": 30, "against": 9, "abstain": 4,
  "turnout": 65, "need": 51, "success": true, "first": true,
  "score": 6040, "best": 6040, "newBest": true,
  "coins": 1380000, "totalCoins": 2160000,
  "reward": { "tourId": "L3", "points": 80, "badge": "tariff_approved", "badges": ["tariff_approved"], "status": "sent", "at": 1795800000000 },
  "badges": ["tariff_approved"], "problem": "…", "suspicious": false }
```

Ошибки: `404 no_run` — нет такого `runId` или он чужой.

## 5. Викторина

### `POST /quiz/finish`

Запрос:
```json
{ "tourId": "L3", "total": 5, "firstTry": 4, "second": 1, "hardFirst": 1, "seconds": 74, "trips": 2 }
```

Поля:
- `firstTry` — верно с первой попытки;
- `second` — со второй;
- `hardFirst` — сложных вопросов с первой;
- `trips` — сколько раз игрок споткнулся о преграду.

Правила:
- Подозрительно, если `total < 3` или `seconds < total×4`. Тогда `coins = 0`.
- Деньги начисляются только за первый проход квиза этого тура:
  - (`firstTry − hardFirst`) × 20 000;
  - плюс `hardFirst` × 50 000;
  - плюс `second` × 5 000;
  - минус `trips` × 1 000;
  - итог не меньше 0.
- `quizBest[tourId]` = лучшая доля верных с первой попытки.
- Значок `zhkh_expert` (100 баллов) выдаётся один раз, когда у всех 7 туров `quizBest ≥ 0.8`.

Ответ:
```json
{ "coins": 135000, "totalCoins": 2295000, "paidBefore": false, "suspicious": false,
  "badge": null, "reward": null }
```

## 6. Дом

### `GET /house`

```json
{ "fixed": ["door","light"], "decor": [], "won": ["L1","L2"],
  "coins": 480000, "score": 220, "bonus": 22, "claimable": true }
```

- `score` — сумма `pts` отремонтированного.
- `bonus` = `floor(score/10)`.
- `claimable` — бонус дня ещё не забран сегодня и `score > 0`.

### `POST /house/buy`

Запрос: `{ "id": "walls" }`. Ответ — как у `GET /house`.

Обычный ремонт можно покупать только после победы в L2 (игрок стал председателем). Ремонты-решения купить нельзя: они появляются сами после победы в своём туре.

Ошибки:
- `409 already` — уже отремонтировано;
- `403 not_chairman` — L2 ещё не выигран;
- `403 no_vote` — это решение собрания, купить нельзя;
- `402 no_money` — не хватает бюджета;
- `404 no_item`.

| id | Тип | Тур | Цена, ₸ | Очки |
|---|---|---|---|---|
| door | ремонт | — | 600 000 | 120 |
| walls | ремонт | — | 1 500 000 | 150 |
| light | ремонт | — | 300 000 | 100 |
| pit | ремонт | — | 300 000 | 60 |
| yard | ремонт | — | 1 000 000 | 110 |
| cameras | ремонт | — | 800 000 | 100 |
| playground | ремонт | — | 4 000 000 | 180 |
| letnik | решение | L4 | — | 160 |
| antenna | решение | L5 | — | 240 |
| lift | решение | L6 | — | 220 |
| roof | решение | L7 | — | 140 |
| basement | решение | L7 | — | 160 |

Полный список с названиями — `PROBLEMS` в `src/content.js`.

### `POST /house/claim`

Бонус дня в приложение: `bonus` баллов, раз в сутки.

Ответ: `{ "reward": { "tourId": "daily", "points": 22, "status": "sent", "at": … }, "house": { … } }`.

Ошибки: `409 claimed` — сегодня уже забран.

## 7. Рейтинг и награды

### `GET /leaderboard?scope=complex|city|house`

- `complex` — лучшие игроки ЖК;
- `city` — игроки города;
- `house` — лучшие дома: `name` = «ЖК · игрок», `best` = очки дома.

```json
{ "scope": "complex", "complexName": "ЖК «Нұрлы»",
  "top": [ { "rank": 1, "name": "Динара", "best": 1460, "me": false } ],
  "mine": { "rank": 7, "name": "Әмина", "best": 640, "me": true } }
```

В `top` — первые 8 мест. `mine` — место игрока, или `null`, если он ещё не играл.

### `GET /rewards`

```json
{ "guest": false, "rewards": [ { "tourId": "L1", "points": 60, "badge": "initiative_group", "status": "sent", "at": … } ] }
```

`status`:
- `sent` — передано в приложение;
- `needs_login` — гость: награда ждёт входа.

## 8. Telegram: сообщения от бота

### `POST /tg/write`

Запрос: `{ "allowed": true }`. Ответ: `{ "ok": true, "allowed": true }`.

Игра сообщает, разрешил ли игрок боту писать ему (`WebApp.requestWriteAccess`). Запрос уходит:
- сразу после входа по номеру;
- после ответа на напоминание в доме;
- после нажатия «Разрешить» в настройках.

Боту это нужно, чтобы присылать сертификаты, итоги и напоминания. Сервер хранит флаг у пользователя и шлёт сообщения через Bot API `sendMessage` / `sendDocument` только тем, у кого `allowed: true`. Если Bot API ответил `403 Forbidden` — игрок заблокировал бота, флаг нужно сбросить.

Что бот может присылать (решает E-KNOT):
- сертификат после победы в L7 или за значок `zhkh_expert`;
- «вас ждёт собрание» через N дней без игры;
- итоги розыгрыша лучших домов.

Кнопка в сообщении может открывать игру: `https://t.me/korshiler_game_bot/play`.

## 9. Что проверить при подключении

1. Откройте `https://amicherry.github.io/korshiler/?api=<ваш адрес>&token=<тестовый токен>`.
2. Пройдите пролог и тур 1: должны прийти `/auth` → `GET /profile` → `PUT /profile` → `/tours/start` → `/tours/finish`.
3. Тур 2 должен открыться только после победы в туре 1. Без неё — `403 locked`.
4. Ремонты в доме: покупка до победы в L2 → `403 not_chairman`; без бюджета → `402 no_money`.
5. Отправьте `/tours/finish` дважды с одним `runId` — монеты не должны удвоиться.
